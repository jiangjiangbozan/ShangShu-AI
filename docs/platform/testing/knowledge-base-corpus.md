# 知识库语料与切片统计

> 统计时间：2026-11-27 · 数据源：`ai_agent`（MySQL）+ `ai_agent_knowledge`（Elasticsearch）
> 口径：仅统计 `deleted=0` 的有效记录；切片 token 数为分片入库时写入的 `token_count`

## 结论

- 全库 **62 篇文档 / 1,155 条切片 / 约 19.2 万 token**，覆盖项目自文档与三条主流技术栈的官方文档。
- **链路零丢失**：MySQL 切片数 1,155 与 ES 向量数 1,155 完全一致，说明「解析 → 切片 → 向量化 → 写索引」四步对账平衡。
- **切片粒度健康**：空切片 0；长度 12–997 字符、均值 665 字符，平均 165–178 token，落在 `chunkSize=800` + `chunkOverlap=200` 的设计区间。
- 换向量模型（nomic → 百炼 qwen3.7）后，50 题全链路 **Recall@5 0.940 / nDCG@5 0.870 / 命中率 94%**（详见 `rag-eval-report.md`）。

## 三、语料构成

### 批次 A：项目自文档（27 篇 / 338 切片 / 5.6 万 token）

取自仓库 `docs/`：README、架构说明、工作流节点指南、四份 API 文档、评测报告，以及 `docs/kb/` 下 17 篇技术栈知识文档（含 ADR、Agent、前后端实践）。语料直接来自仓库文件，可随代码演进重新入库。

### 批次 B：官方技术文档（33 篇 / 747 切片 / 12.3 万 token / 36.4 万字符）

全部取自官方仓库的文档源（AsciiDoc / Markdown 原文），不是二手博客；每篇记录仓库、分支、路径、许可证与抓取时间，清单见 `dev/rag-corpus/MANIFEST.md`。

| 技术栈 | 篇数 | 字符数 | 覆盖内容 |
|---|---|---|---|
| Spring AI | 18 | 250,218 | RAG 总览与模块、ChatClient、Advisor、Tool Calling、结构化输出、可观测性、LLM-as-Judge、ChatMemory、Prompt、语义缓存、多模型 |
| MyBatis-Plus | 12 | 49,359 | 快速开始、安装、逻辑删除、自动填充、主键策略、批处理、高级特性、SQL 注入器、类型处理器、分页插件、多租户、乐观锁 |
| RabbitMQ | 3 | 64,727 | AMQP 概念模型、队列特性、消费者预取与限流 |

> 语料本体不入 Git（可由 `dev/rag-corpus/download_corpus_b.py` 一键复现），仓库只保留脚本、清单与统计，避免第三方文档膨胀与许可风险。

## 四、新增语料的流程

```bash
# 1. 抓取（或把自有文档放入目录）
cd dev/rag-corpus && python download_corpus_b.py

# 2. 入库（自动按名称复用知识库，分批 multipart 上传）
python upload_corpus_b.py

# 3. 若更换了向量模型，先原地重算历史分片向量，再验证
cd ../rag-eval && python reembed.py --index ai_agent_knowledge

# 4. 对账：MySQL 切片数应等于 ES 向量数
curl "http://localhost:9200/ai_agent_knowledge/_count"
```
